# Пара 1. Введение в машинное обучение — сценарий преподавателя

## Логика занятия

Первые 28 минут отвечают на вопрос «что это за курс и куда мы идём». Затем студенты получают карту задач и семейств алгоритмов. Только после этого мы разбираем квартиру как один сквозной пример supervised regression и проходим путь от данных до проверки качества. Не начинайте рассказ с терминов `fit`, `loss` или примера квартиры: сначала дайте контекст.

Пара рассчитана на 90 минут. На слайдах — опорные тезисы; развёрнутый текст для устного объяснения находится в speaker notes каждого слайда. Подробный разбор KNN — на третьей неделе. Методический ориентир — первая лекция [«Тренировок по ML 1.0» Яндекса](https://www.youtube.com/watch?v=k3UJOG-DKHE&list=PLXtiZNKIobF5wGW0ExSn47db1I8uYnfIC), но порядок вводной пары адаптирован под этот курс.

## До пары

1. Подготовьте короткое личное представление: кто вы, чем занимаетесь, почему ведёте курс. Не выдумывайте опыт или регалии.
2. Откройте [программу курса](../../syllabus/course_program.md) и проверьте, что план недель 1–15 актуален. Слайды 5–7 следуют ей напрямую.
3. Проверьте доступность [репозитория курса](https://github.com/mart1ny/University-level-machine-learning-course), локального Python/Jupyter и ссылки на онлайн-встречу.
4. Подумайте, где студенты смогут задать вопросы после пары. Точных весов, порогов и дедлайнов оценивания не объявляйте: рейтинговая система в разработке.
5. Запустите презентацию через локальный сервер по `README.md`. Проверьте слайд 8 (roadmap), формулы и режим докладчика `S`.

| 5 | Недели 1–5: корректный эксперимент → KNN → оптимизация → линейная регрессия. Покажите зависимости между темами. |
| 6 | Недели 6–10: усложнение модели, классификация и её метрики, деревья, cross-validation. |
| 7 | Недели 11–15: ансамбли, SVM, признаки и пайплайны, обучение без учителя. |
| 8 | Roadmap повторяет три предыдущих слайда визуально. Не зачитывайте все карточки; проведите по крупным этапам. |
| 9 | На практике сначала гипотеза, затем изменение одного фактора и вывод. Спросите о scaling для KNN. |
| 10 | Python/Jupyter/GitHub — базовые инструменты. Виды контроля предварительны; рейтинг и баллы не утверждены. |
| 11 | В обычном правиле зависимость задаёт человек, в ML конкретная зависимость подбирается по данным. Человек всё равно задаёт задачу и критерий успеха. |
| 12 | Главное деление: при supervised известны ответы в обучающих примерах; при unsupervised целевой переменной нет. «Учитель» — это метка, а не преподаватель. |
| 13 | Регрессия даёт число, классификация — категорию. Классификатор может дополнительно выдавать вероятности. |
| 14 | Кластеризация, снижение размерности и поиск аномалий — разные постановки без target. Кластеры не обязаны совпасть с бизнес-категориями. |
| 15 | Каждое семейство строит прогноз своим способом: соседи, веса, вопросы, ансамбль, граница. Не заявляйте, что одно всегда лучше другого. |
| 16 | K-Means/DBSCAN — алгоритмы кластеризации; PCA — снижение размерности. Это не три синонима. |
| 17 | Перед раскрытием ответа соберите варианты в чате. А — регрессия; Б — классификация; В — кластеризация. Попросите объяснить почему. |
| 18 | Квартира — supervised regression. Спросите, каких признаков не хватает. Теперь пример уже привязан к карте задач. |
| 19 | Строка — объект; признаки — известные характеристики; цена — target. Числа вымышлены, данных слишком мало для реальной модели. |
| 20 | Формула `\mathcal D=\{(x_i,y_i)\}_{i=1}^{n}`: n обучающих объектов, у каждого признаки и известный ответ. Попросите найти x и y в таблице. |
| 21 | `fit()` учится по известным ответам, `predict()` получает только признаки. `\hat y` — прогноз, не истинный `y`. Разные алгоритмы реализуют fit по-разному. |
| 22 | Train нужен для обучения, validation — для выбора варианта, test — для заключительной оценки. Не подбирайте модель по test. |
| 23 | Средняя цена из train — простейший baseline. MAE — средняя величина ошибки на test в единицах цены. Уточните роль loss/metric, не делайте из них искусственных противоположностей. |
| 24 | Веса и сдвиг линейной модели определяются из данных; число соседей k у KNN задают до обучения и подбирают по validation. |
| 25 | Пройдите весь маршрут на квартире. Ошибка может означать проблему в постановке или данных, а не только «плохой алгоритм». |
| 26 | На следующей практике студенты пройдут маршрут в Jupyter. До неё проверяют Python, Jupyter, Git и GitHub. |
| 27 | Три финальных вопроса: цена квартиры — какой тип задачи? Клиенты без меток? Почему не оцениваем только по train? |

## Формулы: как проговаривать

Формулы находятся в `index.html` как LaTeX и рендерятся локальным KaTeX. На первой паре не нужно выводить их строго; важно связать символы с уже понятным примером.

| Слайд | Запись | Простое прочтение |
|---:|---|---|
| 13 | `\hat y\in\mathbb R` / `\hat y\in\{0,1,\ldots,K-1\}` | При регрессии ответ — число, при классификации — один из классов. |
| 20 | `\mathcal D=\{(x_i,y_i)\}_{i=1}^{n}` | В выборке n пар: признаки квартиры и её цена. |
| 21 | `\hat y=f(x;\theta)` | Обученная модель принимает признаки и выдаёт прогноз. `\theta` — общая запись её обученного состояния, не обязательно веса KNN. |
| 23 | `\hat y_{\mathrm{base}}=\frac1n\sum y_i` | Всем новым объектам предсказываем среднюю цену обучающей выборки. |
| 23 | `\operatorname{MAE}=\frac1m\sum\lvert y_j-\hat y_j\rvert` | Усредняем абсолютную ошибку на m отложенных примерах. |
| 24 | `\hat y=w^{\mathsf T}x+b` | Линейная модель складывает признаки с обученными весами и добавляет сдвиг. |

## Возможные вопросы

**«Будет ли Deep Learning?»** Ядро курса — классическое ML. Нейросети не входят в подробную 15-недельную программу.

**«Зачем математика, если есть sklearn?»** Чтобы понимать, почему модель ведёт себя именно так, как её оценить и отладить. Формулы будут вводиться вслед за интуицией.

**«Какой алгоритм лучший?»** Универсально лучшего нет: постановка, данные, метрика и требования к скорости/объяснимости определяют выбор. Начинаем с baseline и корректного сравнения.

**«Сколько баллов за ДЗ?»** Рейтинговая система пока в разработке. Финальные правила опубликуем до оценивания соответствующих работ.

Введение в машинное обучение

Курс, правила оценивания и первые задачи ML

0–2 мин. Представьтесь: чем занимаетесь, почему ведёте курс. Если есть собственный ML-кейс, назовите задачу и полученный результат за 60–90 секунд. Сегодня: программа и польза курса, правила оценивания, затем первая вводная по ML. Не обещайте трудоустройство после одного курса.

2–5 мин. Обозначьте результат через действия студента. Например: получил таблицу, понял, что предсказывать, построил простое решение, честно оценил и объяснил его. Фокус курса — классическое ML; он создаёт базу для дальнейшего изучения нейросетей.

О чём будем говорить

От данных к первым моделям

  1. Постановка задачи, признаки и целевая переменная
  2. Подготовка данных, разбиение и оценка качества
  3. Ближайшие соседи и расстояния
  4. Линейная регрессия и градиентный спуск
  5. Регуляризация, классификация и метрики
5–8 мин. Проведите аудиторию по темам курса без календаря: сначала формулируем задачу и учимся проверять качество, затем разбираем модели и способы обучения. Математику вводим по мере необходимости. Это маршрут курса, а не список тем сегодняшней пары.

О чём будем говорить

От отдельных моделей к полному решению

  1. Деревья решений и подбор гиперпараметров
  2. Случайный лес, градиентный бустинг и CatBoost
  3. SVM и работа с признаками
  4. Pipeline, кросс-валидация и интерпретация
  5. Кластеризация, PCA и самостоятельный ML-эксперимент
8–10 мин. Продолжите маршрут: от отдельных моделей к ансамблям, затем к воспроизводимому эксперименту. Объясните связи между темами, не закрепляя их за неделями. Соревнования дадут возможность собрать изученное в самостоятельное решение.

Теперь о предмете курса

Что вообще делает машинное обучение?

Обычное правило

Человек явно записывает, как из входных данных получить ответ.

Обучение по данным

Алгоритм подбирает зависимость по примерам, а затем применяет её к новым объектам.

33–36 мин. Правила и модели не противоположны абсолютно: обучение — тоже программа с заранее выбранным алгоритмом. Отличие в том, что конкретная зависимость определяется данными. Спросите: где всё-таки нужен человек? Ответ: постановка, данные, метрика, решение о применении.

Постановка важнее алгоритма

Когда ML вообще уместен?

Есть задачарешение после прогноза можно сформулировать

Есть данныедостаточно репрезентативных примеров и законный доступ к ним

Есть проверкаможно сравнить решение с простым правилом и измерить ошибку

Если надёжное правило решает задачу, ML может быть не нужен.

36–38 мин. После определения ML задайте вопрос «почему не просто if/else?». Если задача строго описывается коротким устойчивым правилом, нет смысла усложнять. ML полезен, когда зависимость сложна, есть данные и можно измерить выигрыш. Пример: проверка возраста по дате рождения — правило; оценка вероятности оттока — кандидат для ML. Подчеркните ограничения: сдвиг данных, приватность, стоимость ошибок.

Главное деление задач

Есть правильный ответ для обучения?

С учителем

Для каждого учебного объекта известен ответ y. Модель учится предсказывать его для новых объектов.

Цена квартиры, спам-письмо

Без учителя

Готового ответа y нет. Ищем структуру в самих признаках.

Группы клиентов, сжатие признаков

Ещё есть обучение с подкреплением: выбор действий по награде. Его здесь подробно не изучаем.

44–47 мин. Сопоставьте с квартирой: известные цены прошлых сделок — учитель. Без target можно, например, искать группы похожих квартир. Это два режима обучения, а не две библиотеки. Кратко упомяните обучение с подкреплением: агент учится выбирать действия по награде; оно за пределами основного курса.

Обучение с учителем

Ответ — число или категория?

Регрессия

Предсказываем число: цену, спрос, время доставки.

\[\hat y\in\mathbb R\]

Классификация

Предсказываем класс: спам/не спам, отток/остался.

\[\hat y\in\{0,1,\ldots,K-1\}\]
47–50 мин. Дайте аудитории два контрастных примера и попросите определить тип. Формулы здесь лишь фиксируют тип результата: действительное число или один из конечного набора классов. Классификатор может также выдавать вероятности классов — это отдельно разберём позже. Если кто-то спрашивает про прогноз рейтинга 1–5, допустимы разные постановки; зависит от смысла и метрики.

Обучение без учителя

Ищем структуру без целевой переменной

Кластеризацияпохожие объекты собираются в группы

Снижение размерностипредставляем данные меньшим числом координат

Аномалииищем необычные наблюдения — обзорно

Нет гарантии, что найденные группы совпадут с «настоящими» категориями.

50–52 мин. Покажите разные цели без учителя: кластеризация, снижение размерности, поиск аномалий. Кластер — результат выбранных признаков и меры близости, а не заранее известный класс. K-Means и DBSCAN группируют объекты; PCA уменьшает число координат. Подробности на неделе 15. Обнаружение аномалий также бывает с учителем, если есть размеченные примеры.

Не путать постановку и метод

«Классификация» — задача, «дерево» — алгоритм

Вопрос к задаче

Какой ответ нужен? Есть ли размеченные примеры? Какова цена ошибки?

Вопрос к алгоритму

Как строится зависимость? Какие данные подходят? Как проверим, что он лучше baseline?

Одна задача обычно допускает несколько разных алгоритмов.

55–57 мин. Для спама можно попробовать логистическую регрессию, дерево, бустинг, нейросеть. Название задачи не диктует модель. И наоборот: KNN может решать и регрессию, и классификацию. Это частый источник путаницы у новичков. Спросите, может ли дерево предсказывать цену квартиры; ответ да — дерево регрессии.

57–59 мин. Короткий обзор механизмов, без вывода формул и сравнения победителей. Все эти семейства допускают варианты для регрессии и классификации. Обсудите один пример: KNN ищет похожие квартиры, дерево задаёт пороговые вопросы. Остальные методы разберём в соответствующих неделях.

59–62 мин. Объясните смысл обучения без команд библиотеки. В качестве примера возьмите линейную модель цены по площади: сначала у неё неудачный наклон, затем алгоритм находит более подходящие коэффициенты. Функция потерь задаёт, какие ошибки штрафовать. Не каждый алгоритм буквально повторяет эти шаги: линейная модель может решать систему уравнений, дерево выбирает разбиения, KNN сохраняет примеры. Снижение ошибки на обучении ещё не гарантирует качества на новых квартирах.

Обобщение на новые данные

Недообучение и переобучение

Недообучение · underfitting

Модель слишком груба и пропускает зависимость.

Ошибка велика и на train, и на новых данных.

Всем квартирам назначает одну цену.

Переобучение · overfitting

Модель подстраивается под шум и детали train.

На train ошибка мала, на новых данных велика.

Запомнила цены учебных квартир.

Это типичные признаки. Причину проверяем по данным и экспериментам.

62–65 мин. Спросите, почему модель с нулевой ошибкой на учебных квартирах может оказаться бесполезной. При недообучении выбранная модель не улавливает существенную зависимость. При переобучении она использует случайные особенности обучающей выборки. Пример с одной ценой иллюстрирует слишком грубое решение для неоднородных квартир, а не утверждает, что константа всегда плоха. Разрыв ошибок также бывает из-за сдвига распределения. Следующий слайд объясняет механизмы через bias и variance.

Почему сложнее не всегда лучше

Bias–Variance Tradeoff

Bias · смещениеНасколько средний прогноз по разным train отличается от истинной зависимости

Variance · разбросНасколько меняется прогноз, если обучить модель на другом train

Для квадратичной ошибки: ожидаемая ошибка = Bias² + Variance + шум.

Классическая схема. Гибкость выбираем по validation.

65–72 мин. Предложите мысленный эксперимент: много раз собираем разные обучающие наборы одинакового размера из одного распределения и предсказываем цену одной и той же квартиры. Bias — отличие среднего прогноза от истинной средней цены при этих признаках. Variance — разброс прогнозов между такими обучениями. Грубая модель может стабильно ошибаться, гибкая — сильно реагировать на состав train. На схеме Bias² падает, variance растёт, их сумма с неустранимым шумом даёт ожидаемую квадратичную ошибку. Шум показан пунктирной горизонталью. Это иллюстрация типичного режима, не универсальный закон формы кривых. Не называйте variance разбросом цен квартир или ошибками одной модели. При переобучении пробуем ограничение глубины, регуляризацию или больше независимых данных; при недообучении — более выразительную модель и полезные признаки. Выбор проверяем на validation. Источники: https://www.teach.cs.toronto.edu/~csc311notes/bias_variance_decomposition/bv.html и https://scikit-learn.org/stable/auto_examples/ensemble/plot_bias_variance.html .

Честная проверка

Успех на знакомых квартирах ещё не успех

Trainобучаем модель и строим простой baseline

Validationсравниваем варианты и выбираем настройки

Testодин раз оцениваем выбранное решение

72–75 мин. Аналогия: проверять студента по ответам, которые он только что заучил, бессмысленно для оценки переноса знаний. В реальной практике схемы разделения зависят от данных, времени и объёма выборки; здесь только принцип. Нельзя подбирать гиперпараметры по test. Позже вернёмся к этому подробно.

Почему оценка бывает обманчивой

Утечка данных · Data Leakage

В обучение или настройку попадает информация, которая была бы недоступна при честном прогнозе.

Ответ в признакахКомиссия, вычисленная из итоговой цены продажи

Пересечение выборокДубликаты или связанные объекты в train и validation

Сначала разделяем данные. Обработку обучаем на train. Test сохраняем для финальной оценки.

75–79 мин. Покажите четыре механизма утечки. Комиссия, равная проценту итоговой цены, косвенно раскрывает target. Действия клиента после даты прогноза раскрывают будущее. Копии одного объявления в разных выборках позволяют узнать учебный объект. Средние для заполнения пропусков и отбор признаков нельзя вычислять по всей выборке до split: validation и test начинают влиять на обучение. Если предсказываем для новых клиентов, делим по клиентам; если будущее — по времени. Связанные объекты опасны, когда такое пересечение не соответствует сценарию применения. Постоянный подбор модели по test тоже загрязняет оценку. Высокое качество само по себе не доказывает утечку.

Простая точка сравнения

Модель должна быть полезнее простого прогноза

Baseline

Для каждой квартиры предсказываем медиану цен из train.

MAE

Средняя абсолютная ошибка. Чем меньше, тем лучше.

\[\operatorname{MAE}=\frac{1}{m}\sum_{j=1}^{m}|y_j-\hat y_j|\]

Ошибки 1, 2 и 1 млн ₽: MAE ≈ 1,33 млн ₽

Baseline и модель сравниваем на одних отложенных данных.

79–82 мин. Медиану вычисляем только по train. Для MAE медиана — естественный константный baseline: она минимизирует сумму абсолютных отклонений на train. Попросите посчитать (1+2+1)/3 и назвать единицу измерения. Числа учебные. Модели сравниваем по validation, а test оставляем для финальной оценки выбранного решения. Средняя цена тоже возможный baseline; она оптимальна среди констант для квадратичной ошибки, не для MAE.

Что задаём, а что учим

Параметр ≠ гиперпараметр

Параметр

Определяется из обучающих данных. У линейной модели — веса w и сдвиг b.

\[\hat y=w^{\mathsf T}x+b\]

Гиперпараметр

Задаётся до обучения и настраивается по validation. У KNN — число соседей k.

82–84 мин. Не погружайтесь в вывод линейной модели. Верхнее T — запись скалярного произведения. Спросите, что из примеров будет искать алгоритм, а что нужно выбрать до fit. В строгом смысле выбор гиперпараметров сам является процедурой настройки по данным, но это не внутренние параметры одной обученной модели. Test для такого выбора не используем.
